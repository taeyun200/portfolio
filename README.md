# 포트폴리오 사이트 운영 안내

> 6개월 뒤의 나(또는 이어받는 AI)를 위한 문서. 설계 배경은 [`docs/PRD.md`](docs/PRD.md).

- 사이트: https://taeyun-portfolio.pages.dev
- 편집: https://taeyun-portfolio.pages.dev/edit/
- **검색엔진에 노출되지 않는다.** 링크를 아는 사람만 들어온다 (2026-07-31 결정)

---

## 1. 가장 자주 하는 일

### 새 산출물 올리기 (약 10분)

1. `/edit` 접속 → 비밀번호 로그인
2. **`백업 내려받기`를 먼저 누른다.** 아래 §5 참조
3. `+ 새 프로젝트` → 폼을 채운다
   - **ID**는 영문 소문자·숫자·하이픈만. 스크린샷 폴더 이름이 되므로 나중에 바꾸면 이미지가 끊긴다
   - `한 줄 요약`은 카드에 그대로 보이므로 60자 안에서 끝낸다
   - `결과`는 **쓸 내용이 있을 때만.** 비워도 저장된다 (§6)
4. `전체 저장` → 사이트에 즉시 반영. 배포 불필요

> 저장이 거부되면 몇 번째 프로젝트가 문제인지 화면에 표시된다. ID 형식, 제목·문제 빈칸, 날짜 형식, ID 중복이 거부 사유다.

### 내용 수정

`/edit`에서 고치고 `전체 저장`. 배포 필요 없음. **데이터는 코드가 아니라 KV에 있다.**

### 받은 문의 확인

`/edit` 상단 `받은 문의` 를 펼친다. 성함·연락처·내용·접속 지역·시각이 보이고 건별 삭제된다.

**메일 알림은 없다.** 로그인해야 보인다. 노션으로 알림 보내는 방안을 검토했고 기술적으로 가능함을 확인했으나 보류 상태다 (§8).

## 2. 스크린샷 올리기

이미지만은 `/edit`으로 못 올린다. **저장소 파일**이라 배포가 필요하다.

```bash
# 1. 폴더에 이미지를 넣는다. 폴더명 = 프로젝트 ID
#    assets/screenshots/<프로젝트ID>/아무이름.png

# 2. 목록 파일을 다시 만든다 (폴더에서 가장 최근 이미지를 자동으로 고른다)
node scripts/gen-screenshots.js

# 3. 배포 (§3)
```

**PC에 개발환경이 없을 때**는 GitHub 웹에서 `assets/screenshots/<ID>/` 에 업로드해도 된다. 단 그 경우 `js/screenshots.js`를 손으로 고쳐야 한다 — 2단계를 대신 돌려줄 사람이 없기 때문이다.

**이미지는 넣기 전에 줄인다.** 폭 1200px 이하 권장. 프로필 사진이 1.1MB로 올라가 있던 적이 있고, 방문자마다 그걸 내려받았다.

## 3. 배포

코드(HTML/CSS/JS/Functions)를 고쳤을 때만 필요하다. **프로젝트 내용 수정은 배포가 필요 없다.**

```bash
npx wrangler pages deploy . --project-name taeyun-portfolio --branch main --commit-dirty=true
```

> **GitHub 자동 배포를 믿지 말 것.** 저장소는 Pages에 연결돼 있지만 2026-07-31 기준 push가 빌드를 트리거하지 못했다(5분 이상 대기해도 반응 없음). 위 명령으로 직접 올리는 것이 확실하다. `git push`는 이력 보존용으로 따로 해 둔다.

### 배포 후 확인

**변경이 안 보이면 대개 CDN 캐시다.** 브라우저 `Ctrl+F5`를 먼저 해 보고, 그래도 그러면 배포 전용 주소(`https://<배포ID>.taeyun-portfolio.pages.dev`)로 확인한다. 여기서 정상이면 배포는 성공했고 엣지 캐시가 남은 것뿐이다. 실제로 이미지와 HTML 모두에서 겪었다.

### 자체 점검

```bash
node scripts/save.test.mjs
```

저장 검증 규칙과 구 형식(v1) 데이터 변환을 확인한다. 의존성 없음. **`functions/api/admin/save.js` 나 `functions/_lib/projects.js` 를 고쳤으면 배포 전에 반드시 돌린다.**

## 5. 백업

**KV 키 하나에 전부 들어 있다.** 잘못 저장하면 통째로 날아간다.

- `/edit` 의 `백업 내려받기` → JSON 파일로 저장. **크게 고치기 전에 습관적으로 누른다**
- 되돌리려면 그 JSON을 보고 `/edit`에서 손으로 복구하거나, 아래 명령으로 통째로 되돌린다

```bash
npx wrangler kv key put projects --path 백업파일.json \
  --namespace-id 3b5682746008416ab131dab3c2f59f21 --remote
```

> `--remote` 를 빼면 로컬 저장소를 보게 되어 아무 일도 일어나지 않는다. 조회할 때도 마찬가지다.

`functions/_lib/default-projects.js` 는 KV가 완전히 비었을 때만 쓰인다. **KV를 초기화해도 글이 안 날아가게 하려면**, 내용을 크게 채운 뒤 백업 JSON을 이 파일에 반영해 두면 된다.

## 6. 게시 전 개인정보 체크리스트

학교 업무 산출물에는 학생 정보가 섞여 들어가기 쉽다. **스크린샷을 올리기 전에** 확인한다.

- [ ] 이름·학번·생년월일이 보이지 않는가
- [ ] 성적·등급·석차가 개인 단위로 보이지 않는가
- [ ] 생기부 문장이 그대로 노출되지 않는가
- [ ] 학교명이 특정되는가 — 특정된다면 그래도 괜찮은 내용인가
- [ ] 소수 인원 집단이라 조합만으로 개인이 짚이지 않는가
  (예: `전형 · 모집단위 · 등급 · 합불` 이 한 줄에 있으면 특정될 수 있다)

**하나라도 걸리면 이미지를 빼고 설명만 올린다.** 카드의 `🔒 비공개` 표시는 **저장소가 비공개**라는 뜻일 뿐, 적어 둔 설명은 누구에게나 보인다는 점을 잊지 말 것.
