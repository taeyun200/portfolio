## 0. v0.1 → v0.2 변경 요약

v0.1은 코드를 보지 않고 쓴 역방향 초안이라 실제 구현과 어긋난 부분이 있었다. 이번 판에서 바로잡은 것:

| # | v0.1 서술 | 실제 | v0.2 조치 |
|---|---|---|---|
| 1 | 카테고리 = 자동화/수업자료/업무문서/실험 | 대입·진학지도 / 학교 업무 자동화 / 개인 생산성 자동화 | **실제 것을 채택.** §6 참조 |
| 2 | `status = 공개/비공개` | `status`=진행중/완료, `visibility`=공개/비공개 (별개 필드 2개) | 이름 충돌 해소, `progress`/`visibility`로 확정 |
| 3 | `problem/approach/result` 3단 | `purpose`(목적) / `method`(방법) 2단, result 없음 | **result 신설이 이번 사이클 최대 작업** |
| 4 | F7 "코드 수정 없이 추가" 충족 여부 불명 | `/edit`은 **수정만** 가능, 신규 추가 불가 | P0 결함으로 승격 (W2) |
| 5 | 성공지표 "상세 도달률 40%" | 측정 수단 자체가 없음 (통계·URL 없음) | 측정 가능하게 만들거나 지표를 버리는 결정 필요 (§4) |

## 1. 한 줄 정의

교사가 AI를 활용해 만든 실제 산출물(자동화 도구, 수업 자료, 업무 문서 등)을 한곳에 모아, **문제 → 접근 → 결과** 맥락과 함께 보여 주는 개인 포트폴리오 웹사이트.

---

## 2. 배경 및 문제 정의

(v0.1 유지)

- 산출물이 GitHub, Notion, 로컬 파일, 연수 자료로 흩어져 있어 한 번에 보여 줄 방법이 없다.
- 연수·강의·협업 문의마다 자료를 새로 정리해야 한다.
- 결과물 자체(코드, hwpx, 엑셀)는 비전문가가 열어봐도 가치가 전달되지 않는다. **맥락**이 함께 있어야 한다.
- 스스로도 작업 이력 아카이브가 필요하다.

### 2-1. 현황 스냅샷 (2026-07-31 기준)

| 항목 | 현재 |
|---|---|
| 등재 산출물 | **7건** (대입·진학지도 6, 학교 업무 자동화 1) |
| 스크린샷 보유 | 4건 / 7건 |
| 미사용 카테고리 | 개인 생산성 자동화 (0건 — 탭에 노출 안 됨) |

| 빌드 도구 | **없음** — 정적 HTML + `<script>` 태그, 의존성 0개 |
| 코드 규모 | 약 1,100줄 (JS 550 / CSS 450 / HTML 80) |

## 3. 목표 / 비목표

### 목표
1. 처음 방문한 사람이 **3분 안에** "이 사람이 무엇을 할 수 있는지" 파악하게 한다.
2. 연수·강의·협업 문의로 이어지는 **신뢰 자료** 역할을 한다.
3. 새 산출물 추가가 **10분 이내**에 끝난다. — *현재 위반. §7 F7 참조*

### 비목표
- 블로그/뉴스레터, 회원가입·댓글, 파일 판매·결제, 다국어
- **추가**: 프레임워크 도입 (Next.js/Astro 등). §8 유지보수 요구사항과 정면 충돌
- **추가**: 산출물별 개별 URL의 서버 렌더링 — 필요해지면 그때 (§9 참조)

## 6. 콘텐츠 모델 v2

### 6-1. 확정 스키마

```jsonc
{
  "id":         "grade5-position-convert",  // 영문 slug, 스크린샷 폴더명과 일치 (필수·불변)
  "title":      "5등급 위치변환",
  "summary":    "9등급 시절 대입 결과를 5등급 학생과 같은 축으로 환산",  // 60자 이내 (신설)
  "category":   "대입 · 진학지도",           // §6-2 고정 목록
  "tags":       ["Python", "pandas"],
  "date":       "2026-07-09",               // ISO 8601 (기존 updated "2026.07.09" 대체)
  "problem":    "...",                      // 기존 purpose 이관
  "approach":   ["...", "..."],             // 기존 method 이관 (문자열 또는 배열)
  "result":     "...",                      // 실제 효과 (신설·필수)
  "repo":       "https://github.com/...",   // 선택
  "progress":   "done",                     // in-progress | done (기존 status 개명)
  "visibility": "private"                   // public | private
}
```

**필드 변경 대조표**

| v2 | 현재 코드 | 조치 |
|---|---|---|
| `problem` | `purpose` | 개명 (내용 그대로) |
| `approach` | `method` | 개명 (내용 그대로) |
| `progress` | `status` | 개명 (PRD의 status와 혼동 방지) |
| `date` | `updated` (`"2026.07.30"`) | ISO로 변환 — **정렬을 위해 필수** |
| `summary` | 없음 | 신설. 7건 직접 작성 |
| `result` | 없음 | 신설. 7건 직접 작성 ← **가장 손이 많이 가는 작업** |
| `tags` | 있음 | **데이터는 있으나 화면에 표시되지 않음** — 렌더 추가 |
| media | `js/screenshots.js` (KV 밖) | 현행 유지, §7 F7 각주 참조 |

### 6-2. 카테고리 (고정)

`js/categories.js` 한 줄에서 관리. 항목이 0건인 카테고리는 자동으로 탭에서 숨겨진다.

1. 대입 · 진학지도
2. 학교 업무 자동화
3. 개인 생산성 자동화

> v0.1의 "수업자료" 카테고리는 **해당 산출물이 생겼을 때 추가한다.** 지금 만들면 빈 탭이다.

### 6-3. 핵심 원칙

모든 항목은 `problem → approach → result` 3단을 **반드시** 갖는다. 결과물만 나열된 갤러리는 포트폴리오가 아니다.
→ 저장 API(`functions/api/admin/save.js`)의 검증에 `result` 필수를 넣어 **빈 채로 저장되지 않게 강제한다.**

> #### F7이 왜 P0 결함이었나 → 어떻게 해소했나
> **문제**: `/edit` 페이지는 로그인 후 기존 프로젝트를 **수정·삭제**할 수 있지만, **새 프로젝트를 추가하는 버튼이 없었다.** `js/edit.js`의 폼에는 `id` 입력 필드조차 없었다. 즉 신규 산출물을 올리려면 `functions/_lib/default-projects.js`를 고쳐 배포하거나 KV를 직접 편집해야 했다. 목표 3("10분 이내")과 리스크 "방치 위험"의 대응책이 정확히 F7인데 그게 뚫려 있었다.
>
> **해소**: W2에서 `+ 새 프로젝트` 버튼과 `ID` 입력란을 추가했다. 상세는 §11 참조.
>
> 단, **스크린샷은 예외로 남긴다.** 이미지는 KV가 아니라 저장소 파일(`assets/screenshots/<id>/`)이며 `node scripts/gen-screenshots.js` 실행 후 커밋해야 반영된다. 이미지 업로드를 웹에서 받으려면 R2 도입이 필요한데, 연 몇 건을 위해 저장소를 하나 더 늘릴 이유가 없다. **GitHub 웹 UI로 파일을 올리면 Pages가 자동 배포되므로 실측 10분 안에 끝난다.** 이 우회 경로를 README에 명문화하는 것으로 갈음한다.

### W3 태그 필터를 되돌린 이유 (2026-07-31)

만들어서 배포까지 했다가 사용자 판단으로 제거했다. **태그가 기술 스택(`Python`, `Cloudflare Workers`)이라 이 사이트의 독자와 축이 맞지 않았다.** 동료 교사와 연수 담당자에게 `Cloudflare Workers`로 좁히는 기능은 아무 의미가 없다.

필터 자체가 틀린 게 아니라 **필터의 기준이 틀렸다.** 입시 용어(`수시`, `생기부`, `정시`) 기준이면 유용할 수 있어 `tags` 필드는 데이터에 남겨 두었다. 화면에는 안 나오고 `/edit`에서만 보인다.

> 교훈: 기능을 넣기 전에 "누구의 어떤 축인가"를 먼저 물었어야 했다. PRD §5에 타깃 사용자를 적어 두고도 구현할 때 참조하지 않았다.

### W8 랜딩페이지 리디자인 (2026-07-31)

카드 그리드만 있던 첫 화면에 "이 사람이 무엇을 하는가"를 말하는 문장이 없었다. 히어로를 신설하고 Color Hunt 팔레트(`#C1EBE9` `#FFF7C5` `#F4AE52` `#4F252E`)를 적용했다.

- 히어로 문구: **손이 많이 가는 일은 도구에게, 흩어진 데이터는 한 곳에**
- 지표 스트립(산출물·완료·진행중·최근 갱신)을 히어로 경계에 걸쳐 배치. **모든 숫자는 데이터에서 계산** — 손으로 적으면 항목이 늘 때 조용히 거짓말이 된다
- 카드는 스크롤 진입 시 등장. `.reveal` 클래스를 **JS에서만** 붙여, 스크립트가 죽으면 애니메이션이 사라질 뿐 내용은 남는다
- `prefers-reduced-motion` 존중

> **팔레트 제약**: `#F4AE52`는 흰 배경 위 대비가 1.9:1이라 글자로 쓸 수 없다. 오렌지는 면으로만 쓰고 그 위 글자는 마룬, 링크·숫자는 같은 색상의 4.7:1 변형(`#B35C0F`)을 쓴다.
>
> **모달 덮개 제거**: 상세 창을 열 때 배경을 마룬 55%로 덮었더니 화면 전체가 탁한 붉은색이 되어 눈이 아프다는 지적. 투명으로 바꾸고 모달 자신의 테두리·그림자로 분리했다.

### W2 완료 내역 (2026-07-31)

- `+ 새 프로젝트` 버튼 — 빈 항목을 추가하고 해당 폼으로 스크롤. `id`는 `new-project-N`으로 자동 생성 후 직접 수정.
- **`ID` 입력란 신설** — 스크린샷 폴더명과 맞춰야 하므로 편집 가능하게 노출. 영문 소문자·숫자·하이픈만 허용.
- `백업 내려받기` 버튼 — 현재 편집 중인 전체 목록을 JSON 파일로 저장. KV가 키 하나에 전량을 담는 구조라 저장 사고 시 복구 수단이 없던 문제(§9) 대응.
- **저장 실패 사유 표시** — 기존에는 원인과 무관하게 "다시 로그인해 보세요"만 떴다. 이제 `3번째 프로젝트의 필수 항목이 비어 있습니다` / `ID가 중복됩니다: hapbul`처럼 지목한다.
- **서버 검증 강화** (`api/admin/save.js`) — id 슬러그 형식·제목 공백 검사 추가, **id 중복 거부**. 중복 id는 상세 모달이 엉뚱한 프로젝트를 여는 조용한 버그를 만든다.
- **자체 점검** `node scripts/save.test.mjs` — 검증 규칙과, 기존 7건이 강화된 규칙을 그대로 통과하는지 확인. 의존성 없음.

**남은 한계 (의도된 것)**: 스크린샷은 여전히 저장소 파일이라 웹 편집기로 올릴 수 없다. §7 F7 각주의 GitHub 업로드 경로를 따른다 → W7에서 문서화.

### W1 완료 내역 (2026-07-31)

**필드 이름이 바뀌었다** — `목적→문제`, `방법→접근`, 여기에 `한 줄 요약`·`결과`가 새로 붙었다. 상세 창은 이제 **문제 → 접근 → 결과** 3단으로 표시되고, 결과 문단만 색 테두리로 강조된다.

**기존 KV 데이터는 손대지 않았다.** `functions/_lib/projects.js`의 `normalize()`가 **읽는 시점에** 구 형식(purpose/method/status/updated)을 신 형식으로 바꿔 준다. KV를 직접 수정할 필요가 없고, `/edit`에서 한 번 저장하면 그때부터 KV에도 신 형식이 기록된다. 덤으로 두 API에 중복돼 있던 "KV 읽기 + 시드 대체" 코드가 `loadProjects()` 하나로 합쳐졌다.

- 날짜는 `2026.07.30` → `2026-07-30`(ISO)으로 자동 변환. **W3의 최신순 정렬이 이걸 전제로 한다.** 편집 폼은 `<input type="date">`라 달력에서 고르면 되고 형식을 틀릴 수 없다.
- 편집 화면 상단에 **`요약·결과 미작성 N건 / 7건`** 카운터가 뜨고, 미작성 항목은 주황색 테두리와 `⚠` 표시가 붙는다.

> #### 판단: `result` 필수 검증을 지금 켜지 않은 이유
> PRD §6-3은 "빈 채로 저장되지 않게 강제한다"고 적혀 있다. 그러나 지금 강제하면 **7건의 결과를 다 쓰기 전까지는 어떤 수정도 저장할 수 없다.** 3건 쓰고 중간 저장하는 것조차 막힌다. 그런 규칙은 결국 `-` 한 글자를 채워 넣는 식으로 우회되고, 그러면 규칙의 목적 자체가 사라진다.
>
> 그래서 **필드 존재는 강제하되 빈 문자열은 허용**하고, 대신 편집 화면에서 미작성 건수를 눈에 띄게 세어 보여 주는 쪽을 택했다. 7건 backfill이 끝나면 `save.js`의 `ponytail:` 주석 위치에서 `nonEmptyString`으로 한 줄 바꿔 하드 강제로 전환한다.

**자체 점검 확장** — `node scripts/save.test.mjs`가 v1→v2 변환(필드 이름·날짜 형식), **변환의 멱등성**(normalize는 매 읽기마다 도는데 v2를 다시 건드리면 안 됨), 변환된 구 데이터가 신 검증을 통과하는지까지 확인한다.
