# 포트폴리오 작성 기준

프로젝트를 올리거나 고칠 때의 기준이다. 전역 스킬 `portfolio-upload` 가 이 문서를 읽고 따른다.
기준을 바꾸려면 여기만 고친다.

## 누가, 무엇을 보러 오나

연수·강의·협업을 맡길지 정하는 교사와 담당자다. 이들이 먼저 알고 싶은 것은 **"이 사람이 학교의 어떤
불편을 무엇으로 줄였나"** 이다. 기술 이름은 관심 밖이다. 그래서 모든 글·그림·영상은 쉬운 말로,
무엇이 달라졌는지를 중심으로 쓴다.

## 말투

- **전문용어를 쓰지 않는다.** 꼭 필요하면 일상어로 먼저 말하고 괄호에 원래 말 — "기억창고(데이터베이스)".
- 코드·명령어·파일 경로·영어 약자를 본문에 넣지 않는다. 서비스 이름(노션, 구글 표 문서, 슬랙)은 괜찮다.
- 한 문장에 하나. "~한다" 로 끝나는 현재형.
- **사실만 쓴다.** 숫자는 저장소·문서·결과물에서 확인한 것만. 확인할 수 없으면 쓰지 않는다 — 결과 칸이 비는 편이 지어낸 숫자보다 낫다.
- 학교 이름, 학생·교사 실명, 기숙사·건물 이름처럼 학교가 짚이는 말은 쓰지 않는다.

## 칸

| 칸 | 규칙 |
|---|---|
| `id` | 영문 소문자·숫자·하이픈. 스크린샷 폴더·도식·영상 파일 이름이 된다. 한 번 정하면 바꾸지 않는다 |
| `title` | 무엇인지 알 수 있는 이름. 저장소 이름이 아니라 사람이 부르는 이름 |
| `summary` | **60자 이내** 한 줄. 무엇을 해 주는지. 목록과 대표작 카드에 그대로 보인다 |
| `category` | `js/categories.js` 의 넷 중 하나: 대입 · 진학지도 / 수업 · 평가 / 학교 업무 자동화 / 개인 생산성 자동화 |
| `problem` | 왜 만들었나. 누가 어떤 불편을 겪었는지 2~4문장 |
| `approach` | 어떻게 풀었나. **배열**, 3~7줄. 한 줄에 결정 하나와 그 이유. 기술이 아니라 원리를 쉬운 말로 |
| `result` | 실제로 쓰이고 있다는 근거(누가, 얼마나, 무엇이 줄었나). 없으면 빈 문자열. 맨 앞에 보이는 칸이다 |
| `progress` | `done` / `in-progress` |
| `visibility` | 코드 저장소가 공개면 `public`, 아니면 `private` |
| `date` | 마지막 갱신일(마지막 커밋). `YYYY-MM-DD` |
| `start` | 시작일. 첫 커밋과 문서상 가장 이른 날 중 이른 쪽. `date` 와 같으면 넣지 않는다 |
| `repo` · `site` | 공개 저장소 주소, 공개 사이트 주소. 없으면 넣지 않는다 |
| `feature` · `featureNote` | 대표작 순서(1~4)와 카드 아래 한 줄. **사용자가 정한다** — 요청이 없으면 건드리지 않는다 |
| `shot` | 대표작 카드에서 스크린샷을 자를 위치: `top` / `bottom` / `fit`. 가운데면 넣지 않는다 |
| `video` | `assets/videos/<id>.mp4`. 같은 이름의 `.jpg` 가 포스터 |

`tags` 는 화면에 쓰이지 않는다. 새 프로젝트는 `[]` 로 둔다.

## 스크린샷

- `assets/screenshots/<id>/01-이름.jpg`, `02-…` — 번호 순서대로 실리고 01 이 미리보기가 된다.
- 폭 1200px 이하, JPEG.
- **올리기 전에 README §6 개인정보 체크리스트를 거친다.** 이름·학번·성적이 보이면 그 부분을 모자이크하고, 지울 수 없으면 그 그림은 뺀다. 예시용 가짜 이름이라면 그렇다고 확인된 경우만 그대로 둔다.
- 다 넣었으면 `node scripts/gen-screenshots.js`.

## 구조 도식 — `scripts/diagrams/<id>.json`

좌표는 쓰지 않는다. 열 → 상자 → 화살표만 적으면 `node scripts/gen-diagrams.js <id>` 가 배치한다.

- **C형(기본) — 자료가 머무는 곳.** 열마다 `zone`(점선 구역: "폰 안", "학교 구글 계정", "바깥 서비스")을 주고, 구역을 넘는 화살표의 `label` 에 **무엇만** 넘어가는지 적는다("명단만", "읍·면·동만").
- **A형 — 흐름 한 줄.** 자료가 한 곳 안에서만 움직이면 `zone` 없이 왼쪽 → 오른쪽.
- 핵심 상자 하나에 `"key": true`. 상자 제목은 10자 남짓, 부제(`subs`)는 두 줄까지. 길면 생성기가 경고한다.
- `kind`: `box`(기본) / `chip`(한 줄짜리 보조) / `ghost`(일부러 안 하는 것 — 점선). 화살표 `style`: `arw`(기본) / `ln`(가는 선) / `no`(점선, `"cross": true` 면 ✕).
- 견본: `scripts/diagrams/practicum-kiosk.json`.

```json
{
  "aria": "그림이 말하는 내용 한두 문장",
  "columns": [
    { "zone": "대기실 태블릿", "items": [ { "id": "pad", "title": "숫자판", "subs": ["휴대폰 뒤 네 자리"], "key": true } ] },
    { "zone": "담당 선생님의 구글 계정", "items": [ { "id": "sheet", "title": "표 문서", "subs": ["명단 · 출근 기록"] } ] }
  ],
  "arrows": [ { "from": "pad", "to": "sheet", "label": "출근 한 줄" } ]
}
```

## 설명 영상 — `scripts/videos/<id>.json`

`python scripts/make-video.py scripts/videos/<id>.json` → `assets/videos/<id>.mp4` + 포스터 `.jpg`.

- 장면 순서: `title` → `text`(문제) → `image` 1~3장 → `diagram` → `text`(결과) → `end`. 35~60초.
- `say` 는 내레이션이자 자막. 장면마다 1~2문장, **자막 두 줄(50자 남짓) 안**. 카드 글과 같은 사실만, 같은 쉬운 말로.
- `text` 장면의 `text` 는 화면에 크게 나오는 글(자막은 따로 안 나온다). `say` 와 같아도 된다.
- 음성은 타입캐스트. 키는 저장소 밖 `~/.config/portfolio/.env`(`TYPECAST_API_KEY`, `TYPECAST_VOICE_ID`). 같은 문장은 캐시를 써서 다시 결제하지 않는다. 키가 없거나 막히면 자막 + 배경음으로 만들어진다.
- 견본: `scripts/videos/practicum-kiosk.json`.

## 올리는 순서

1. 글을 정리해 프로젝트 JSON(새 프로젝트는 전체, 고칠 때는 바뀐 칸만)을 만든다.
2. 스크린샷 → `gen-screenshots.js`, 도식 → `gen-diagrams.js <id>`, 영상 → `make-video.py`.
3. `node scripts/upsert-project.mjs <json> --preview` → `npx wrangler pages dev . --port 8788` 로 확인.
4. 확인되면 커밋 · 푸시 · 배포(README §3) → `node scripts/upsert-project.mjs <json> --publish`.
   배포가 먼저다 — 게시 단계는 그림·영상이 라이브에 올라가 있는지 확인하고 없으면 멈춘다.
